# Known limitations

- Directory routing covers 361 UK local-authority districts, but live schedule coverage is published separately and is not UK-wide.
- Most directory adapters remain experimental until controlled-address and operational verification are complete.
- The experimental Bin Day nationwide fallback requires the selected street address as well as postcode, council and opaque property reference. It is disabled by default and requires the server-only `WHAT_BIN_ENABLE_NATIONWIDE_FALLBACK=true` gate. Its provider contract, retention, logging and store disclosures must be approved before that gate is enabled; a code change alone cannot approve those external obligations.
- Knowsley missed reporting currently uses the official council handoff. The resident confirms the returned council reference/status before the app stores it.
- Saved places and reminder preferences are device-local; signing in restores plan access, not the address itself. Opt-in household sharing coordinates a nickname, members and bin actions but deliberately does not upload or restore the council property reference.
- Account removal deletes eligible What Bin records but retains the shared Supabase authentication identity and a minimal product-only suppression marker; underlying identity deletion remains an assisted support request.
- iPad support and portrait/landscape adaptation are enabled, but physical iPad, rotation, Split View, large-text and VoiceOver acceptance are still outstanding before store submission.
- Predictive Back is enabled and its route/back semantics are covered by the committed Android Maestro flow, but the predictive gesture animation still requires physical Android regression testing across supported API/OEM targets.
- Native widgets require an installed native build; a PWA cannot appear in the iOS or Android widget gallery.
- Billing code is present but production payment prompts remain disabled until Apple/Google enrolment, products and sandbox validation are complete.
- Deterministic Maestro flows now cover app-scheme destinations, a synthetic cancelled magic-link return, Android airplane-mode cold start, widget/Live Activity sync boundaries and disabled purchase/restore gates. Real remote council-alert receipt/action, delivered magic-link session exchange, OS widget/Live Activity rendering, iOS hardware offline startup, sandbox billing and upgrade preservation still require the documented physical-device release pass. Push-provider acceptance is not represented as proof that a handset displayed the alert.
- Council-local recycling guidance is configuration-driven where a profile exists; otherwise the app labels general guidance and directs the resident to check locally.
- Area-targeted alerts depend on an approved council source providing non-address round or ward labels. Without that feed, the console permits only council-wide or collection/date targeting and warns the publisher before sending.
- The sponsored bulky-collection marketplace is implemented but deliberately shows no paid provider until a council enables the feature and a real licensed operator has passed approval. Turning it on additionally requires provider terms, Stripe Connect onboarding, platform Stripe keys, production webhook validation, a documented cancellation/refund process and a completed test booking.
- Sponsored bookings use a controlled platform-payment flow: What Bin receives the resident payment, the operator accepts and schedules the job, and the platform releases the operator's share only after completion is recorded. What Bin is therefore operationally responsible for refunds, disputes and provider fulfilment and must complete commercial, tax, insurance and legal review before production activation.
- External partner booking confirmation currently requires an authorised council-console user to record the provider's confirmation reference. Website opens, calls, directions and booking starts are reported only as their actual interaction type and never as revenue.
- A synthetic cancelled native bulky-checkout return is covered without network or payment access. The hosted checkout, success/cancellation association and status reconciliation still need a physical-device pass; native builds may return through the hosted status page until store deep links are approved.
- Private data-quality reports have two durable database budgets: five per dedicated pseudonymous client in 15 minutes/20 per day, and 120 per HMAC-keyed trusted Vercel network identity in 15 minutes. Neither raw client IDs nor IP addresses are stored. The route fails closed with 503 when the network control is unavailable. The release migration schedules the 24-month purge, but production readback and first-run monitoring remain required. Hosting WAF/bot rules are optional defence in depth, not a substitute for these application controls.
- The public Nitro council gateway has a durable 600-per-15-minute HMAC-keyed trusted-network budget and per-provider failure circuits, and fails closed if either database control is unavailable. Its upstream paths also share a 24-second maximum budget within the 30-second function duration. The release migration and configured server secret must be read back before traffic. Hosting WAF/device reputation remains useful defence in depth, especially for shared-NAT and distributed abuse, but is not claimed as an application prerequisite.
